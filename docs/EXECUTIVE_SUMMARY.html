Required workflow

  1. Obtain official training_features.tif, labels.tif, and sample_submission.tif from the authenticated competition data tab; keep source files local and out of Git.
  2. Reuse the canonical cached feature stack, holdout evaluator, and writer. Withhold whole fault segments with a buffer; create catalogue features only from visible segments; pixel-mask visible faults exactly.
  3. Run individual feature leakage canaries (AUC > 0.90 is leakage until resolved). Score pooled distance-weighted Tversky using alpha 0.2, beta 0.8, and the 300 m triangular kernel. Require improvement over the current holdout best before any slot is considered.
  4. Check duplicates against every registry raster, before and after placement: stop if raster rank-correlation exceeds 0.90 or more than 70% of dots lie within 3 px of one registry raster's dots.
  5. Write one unique, single-band float32 GeoTIFF with probabilities in [0,1]. Match the official sample's CRS, shape, transform, bounds, and footprint. Verify no NaN inside the footprint and that outside cells are null/NaN or explicitly masked.
  6. Save SHA-256, full validator JSON, holdout evaluator version, withheld-positive count, 95% CI, unique submission name, and a note of at most 140 characters. Only then show the file and mark it OK TO SUBMIT.
  7. On DrivenData, select the TIFF (or a ZIP with one TIFF), enter the appropriate experiment/submission name and short note, then retain the submission-page receipt. Only the receipt is organizer-confirmed evidence.

The repository includes a local GeoTIFF format preflight script at scripts/validate_submission.py (requires Python dependencies and the official sample template). Format validation alone does not establish scientific performance.

Official format

EPSG:32611; 100 m resolution; same bounds/grid as training; one float32 layer; predictions in [0,1]; null/NaN outside bounds. Always compare directly with the official sample GeoTIFF.
