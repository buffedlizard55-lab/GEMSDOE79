How to make a submission

The short version
  1. Open cblf.html and read the decision banner: it says, in plain words, whether the file is OK to submit.
  2. Download the .tif (or the .zip that contains exactly that one file).
  3. Go to the competition submission page, choose the file, paste the name and note shown on the artifact page, and press Submit.
  4. Copy the score the page returns into registry/score_ledger.csv as an ORGANIZER-CONFIRMED row. Until then the value is only a report.

Source: problem description, “Submission format”. The “Predicted values must be in range [0, 1]” portal error occurs when any in-bounds cell is outside that range or is not a number the portal accepts. The file offered here is finite and inside [0,1] on every in-bounds cell and NaN only outside the footprint, which is exactly the template's pattern.

Which pixels are free, and which are scored

DrivenData staff answered this directly on the competition forum: pixels corresponding to known USGS/INGENIOUS faults are masked out of evaluation, so they do not count toward the penalty terms (thread 11516, 2026-09-16). The metric is the distance-weighted Tversky index with α = 0.2 and β = 0.8 over a 300 m triangular kernel (metric section).

Rules that limit how many files you may submit

  • The problem statement says competitors must choose a single submission for scoring across both prize rounds (competition structure section).
  • The weekly cap and remaining slot count are properties of the account, not of this repository; check them on the submission page.
  • One final submission per participating entity is the rule this repository assumes (DOE Rules §3.4, as read by the project). Confirm it in the official rules before spending a slot.

Verify a downloaded file yourself

Every artifact page publishes the SHA-256 of the exact bytes offered. On Linux or macOS:

shasum -a 256 gems79-cblf-curvefield-20261022.tif

Compare the result with the SHA-256 printed on the artifact page. A mismatch means the download is not the file that was validated.

What “OK TO SUBMIT” means here — and what it does not

It means the file passes every automated check this project can run without the organizer: R1–R8 on the exact bytes, byte-level and placement novelty against the local prior-raster inventory, and a matched-control holdout comparison.

It does not mean the file is expected to beat a particular leaderboard number, that it is the best available choice for the single final submission, or that the organizer will accept it. Those are separate decisions and the artifact page states them separately.
