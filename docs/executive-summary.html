How a future approved submission works

  1. First clear every local gate. Real source provenance, feature-alone leakage canaries, buffered whole-component hide-and-recover, a matched current-best comparison, literal novelty on the surface and final predictions, and the on-disk format checks must pass.
  2. Obtain separate selector approval. The official rules specify up to three submissions per week. Verify the signed-in account’s actual remaining capacity on the submission page. This project cannot see it and never spends a slot automatically.
  3. Download the approved artifact. Use one .tif, or a ZIP containing exactly that single TIFF. Use the candidate’s own unique name and short comment. Do not substitute this rejected research file.
  4. Open the official submission form. Sign in to DrivenData, choose the approved file in “File to submit”, paste its identifying note, and submit only within the verified cap.
  5. Save the actual receipt. Record the uploaded name, file SHA-256, server outcome and score. Only a real submission-page receipt establishes ORGANIZER-CONFIRMED for a file. An offline score or projection never does.

Why the range error is prevented locally

The writer rejects NaN, infinity, negative sentinels and out-of-range values before writing. It does not silently clip or fill model output. It then reopens the TIFF, compares the reference grid and reopens the ZIP. Our conservative export is finite everywhere, with zero outside the irregular footprint and no nodata sentinel. This is a local policy, not a claim that the organizer forbids all outside-footprint NaN.
