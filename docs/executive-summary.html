Why this submission is unique

G79-DZD targets fault damage-zone permeability — the fractured rock adjacent to mapped faults where fault-core sealing is bypassed and permeability concentrates — at an optimal ~200 m cross-fault distance. It is deliberately different from the stopped G79-THVC lane (multi-physics ML ensemble over gravity, magnetics, shallow temperature, sinter, LiDAR scarps) and from every locally available GEMSDOE raster (max |ρ| = 0.0212, max overlap = 0.2456).

How to submit to the competition (when gates clear)

  1. Download the GeoTIFF above using the "Download unique submission GeoTIFF" button.
  2. Confirm locally that python3 scripts/verify_project.py reports all format checks passed and python3 scripts/submission_status.py reports the decision.
  3. Complete the missing gates: obtain DrivenData training data (login required at competition data tab), run holdout-DTI and the leakage canary, and complete the 992-raster registry uniqueness scan.
  4. Request selector approval: only scripts/select_submission.py may set ok_to_submit after re-deriving every gate and binding a selector receipt to the raster SHA-256.
  5. Upload on the DrivenData submissions page: official submissions page. Use the exact file name and the ≤140-character note shown above. Confirm at least one weekly slot remains (official rules allow up to 3 per week; one final entry per entity).
  6. Keep the submission-page receipt with the file hash — only an organizer receipt establishes ORGANIZER-CONFIRMED status.

The "Predicted values must be in range [0, 1]" error

That portal error is caused by stored values outside [0,1] (including nodata sentinels like −3.4e38) anywhere in the TIFF. This generated file enforces the all-finite [0,1] policy at write time: gems57.submission_writer rejects any prediction that is not already finite and in [0,1], never clips or repairs, and gems57.validate re-checks the on-disk bytes. Every pixel outside the footprint is exactly 0.0; every pixel inside is finite and in [0,1]. If you ever see the portal range error, re-run scripts/validate_submission.py on your file — it checks the same conditions locally before you upload.

Limitations

This is a locally generated research raster, not an organizer-validated submission. Holdout-DTI, leakage canary and full registry uniqueness cannot be measured without DrivenData login-gated training data. The public leaderboard observations (historical reports up to 0.4413) are not this project's scores and do not constitute organizer receipts. Format PASS alone is never permission to submit.
